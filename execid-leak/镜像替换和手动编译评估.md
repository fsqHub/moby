# Docker v1.13.1 镜像替换和手动编译评估

## 问题 1：能否替换老旧的容器镜像？

### 当前镜像分析

```dockerfile
# v1.13.1 原始镜像
FROM aarch64/ubuntu:wily
# Ubuntu 15.10 (Wily Werewolf)
# 发布时间: 2015年10月
# EOL（停止支持）: 2016年7月
# 状态: 已过期 8+ 年
```

**问题**：
- ❌ 软件仓库已关闭（`archive.ubuntu.com/ubuntu/dists/wily` 不再可用）
- ❌ 无安全更新
- ❌ apt-get update 可能失败
- ❌ Docker Hub 可能已移除该镜像

### ✅ 可以替换！推荐方案

#### 方案 1：使用 Ubuntu 18.04/20.04（推荐）⭐

```dockerfile
# 替换为现代长期支持版本
FROM arm64v8/ubuntu:18.04
# 或
FROM arm64v8/ubuntu:20.04
# 或（最新 LTS）
FROM arm64v8/ubuntu:22.04
```

**优势**：
- ✅ 仍在支持期内，软件仓库可用
- ✅ 包版本更新，安全性更好
- ✅ 依赖包齐全（build-essential、git、golang 等）
- ✅ Docker Hub 官方维护

**需要调整的地方**：

```dockerfile
# 1. 基础镜像（第18行）
- FROM aarch64/ubuntu:wily
+ FROM arm64v8/ubuntu:20.04

# 2. 包名称可能变化
- btrfs-tools        → btrfs-progs
- python-dev         → python3-dev
- python-pip         → python3-pip
- python-mock        → python3-mock
- python-websocket   → python3-websocket

# 3. Go 安装（可选优化）
# Ubuntu 20.04+ 自带较新的 Go，可以直接用
RUN apt-get install -y golang-1.18
# 或仍然从源码编译 go1.7.5（保持原构建逻辑）
```

**完整替换示例**：

```bash
cd ~/docker-patch-test/moby-1.13.1

# 复制原 Dockerfile
cp Dockerfile.aarch64 Dockerfile.aarch64.ubuntu20

# 修改基础镜像
sed -i 's|FROM aarch64/ubuntu:wily|FROM arm64v8/ubuntu:20.04|g' Dockerfile.aarch64.ubuntu20

# 修改包名（Python 2 → Python 3）
sed -i 's|python-dev|python3-dev|g' Dockerfile.aarch64.ubuntu20
sed -i 's|python-pip|python3-pip|g' Dockerfile.aarch64.ubuntu20
sed -i 's|python-mock|python3-mock|g' Dockerfile.aarch64.ubuntu20
sed -i 's|python-websocket|python3-websocket|g' Dockerfile.aarch64.ubuntu20
sed -i 's|btrfs-tools|btrfs-progs|g' Dockerfile.aarch64.ubuntu20

# 使用新 Dockerfile 构建
export DOCKERFILE=Dockerfile.aarch64.ubuntu20
make build
make binary
```

#### 方案 2：使用 Debian（稳定性优先）

```dockerfile
FROM arm64v8/debian:bullseye
# Debian 11 (Bullseye)
# 发布: 2021年
# 支持到: 2026年
```

**优势**：
- ✅ 以稳定著称
- ✅ 包依赖关系清晰
- ✅ 长期支持

**需要调整**：

```dockerfile
# 1. 包管理器仍然是 apt-get

```

---

#### 方案 3：使用 CentOS Stream 9 / AlmaLinux 9

```dockerfile
FROM arm64v8/almalinux:9
# 或
FROM quay.io/centos/centos:stream9
```

**优势**：
- ✅ 与目标环境（CentOS）一致
- ✅ RPM 生态

**劣势**：
- ⚠️ 需要大量修改 Dockerfile（apt → yum/dnf）
- ⚠️ 包名完全不同
- ⚠️ 工作量较大

**不推荐**，除非有特殊原因需要 RPM 环境构建。

---

#### 方案 4：使用多架构官方镜像（最现代）

```dockerfile
FROM ubuntu:20.04
# Docker 会自动拉取 arm64 变体
```

**优势**：
- ✅ 简洁，无需指定架构
- ✅ 自动适配 aarch64/x86_64
- ✅ 官方维护

**注意**：
- 确保 Docker 支持 manifest list（v18.06+）

## 问题 2：不使用容器手动编译的复杂度评估

### 复杂度：⭐⭐⭐⭐☆（中高）

**结论**：可行，但需要手动安装大量依赖和配置环境。

### 手动编译需要的步骤

#### 阶段 1：安装系统依赖（复杂度：⭐⭐）

Docker 构建依赖的系统包（来自 Dockerfile.aarch64）：

```bash
sudo yum install -y \
    # 基础工具
    git curl wget \
    gcc gcc-c++ make cmake automake \
    # 存储驱动
    device-mapper-devel \
    btrfs-progs-devel \
    # 安全
    libseccomp-devel \
    libapparmor-devel \
    libcap-devel \
    # 系统集成
    systemd-devel \
    libc6-devel \
    # 网络
    iptables \
    iproute \
    # 其他
    sqlite-devel \
    pkg-config \
    # Python（测试用）
    python3-devel \
    python3-pip
```

**预估时间**：30 分钟（包括查找包名差异）

**潜在问题**：
- openEuler 的包名可能与 Ubuntu 不同
- 某些包可能缺失（需要从源码编译）

---

#### 阶段 2：编译 libseccomp（复杂度：⭐⭐⭐）

Docker v1.13.1 需要 libseccomp 2.3.1+，系统版本可能太老：

```bash
# 检查系统版本
rpm -q libseccomp-devel
# 如果 < 2.3.1，需要手动编译

# 下载并编译
cd /tmp
wget https://github.com/seccomp/libseccomp/releases/download/v2.3.1/libseccomp-2.3.1.tar.gz
tar -xzf libseccomp-2.3.1.tar.gz
cd libseccomp-2.3.1
./configure --prefix=/usr/local
make
sudo make install
sudo ldconfig
```

**预估时间**：15 分钟

---

#### 阶段 3：安装 Go 1.7.5（复杂度：⭐⭐）

```bash
# 下载 Go 1.7.5
cd /tmp
wget https://golang.org/dl/go1.7.5.linux-arm64.tar.gz
sudo tar -C /usr/local -xzf go1.7.5.linux-arm64.tar.gz

# 配置环境变量
export GOROOT=/usr/local/go
export GOPATH=$HOME/go
export PATH=$GOROOT/bin:$GOPATH/bin:$PATH

# 验证
go version
```

**预估时间**：10 分钟

---

#### 阶段 4：编译 LVM2（复杂度：⭐⭐⭐⭐）

Docker 的 devicemapper 存储驱动需要静态链接 LVM2：

```bash
# 下载 LVM2 源码
cd /tmp
wget https://mirrors.kernel.org/sourceware/lvm2/LVM2.2.02.103.tgz
tar -xzf LVM2.2.02.103.tgz
cd LVM2.2.02.103

# 修复 ARM64 支持（重要！）
curl -fsSL -o autoconf/config.guess \
    "http://git.savannah.gnu.org/gitweb/?p=config.git;a=blob_plain;f=config.guess;hb=HEAD"
curl -fsSL -o autoconf/config.sub \
    "http://git.savannah.gnu.org/gitweb/?p=config.git;a=blob_plain;f=config.sub;hb=HEAD"

# 配置和编译
./configure \
    --build="$(gcc -print-multiarch)" \
    --enable-static_link
make device-mapper
sudo make install_device-mapper
```

**预估时间**：30 分钟

**潜在问题**：
- 编译可能失败（依赖问题）
- ARM64 平台特殊配置

---

#### 阶段 5：克隆并编译依赖组件（复杂度：⭐⭐⭐）

```bash
# 设置工作目录
export GOPATH=$HOME/go
mkdir -p $GOPATH/src/github.com/{docker,opencontainers}

# 克隆 runc
cd $GOPATH/src/github.com/opencontainers
git clone https://github.com/docker/runc.git
cd runc
git checkout v1.0.0-rc2  # v1.13.1 使用的版本
make static
sudo cp runc /usr/local/bin/docker-runc

# 克隆 containerd
cd $GOPATH/src/github.com/docker
git clone https://github.com/docker/containerd.git
cd containerd
git checkout v0.2.5  # v1.13.1 使用的版本
make
sudo cp bin/containerd /usr/local/bin/docker-containerd
sudo cp bin/containerd-shim /usr/local/bin/docker-containerd-shim
sudo cp bin/ctr /usr/local/bin/docker-containerd-ctr

# 克隆 libnetwork (docker-proxy)
cd $GOPATH/src/github.com/docker
git clone https://github.com/docker/libnetwork.git
cd libnetwork
git checkout v0.8.0-dev.2  # v1.13.1 使用的版本
go build -o docker-proxy ./cmd/proxy
sudo cp docker-proxy /usr/local/bin/docker-proxy
```

**预估时间**：45 分钟

**潜在问题**：
- 版本兼容性
- Go 依赖下载（如果 vendor 不完整）

---

#### 阶段 6：编译 Docker 主程序（复杂度：⭐⭐）

```bash
# 克隆 Docker 源码
cd $GOPATH/src/github.com/docker
git clone https://github.com/moby/moby.git docker
cd docker
git checkout v1.13.1

# 设置环境变量
export AUTO_GOPATH=1
export DOCKER_GITCOMMIT=$(git rev-parse --short HEAD)
export DOCKER_BUILDTAGS="seccomp"

# 编译
./hack/make.sh dynbinary

# 查看产物
ls -lh bundles/1.13.1/dynbinary-daemon/
# dockerd-1.13.1
# docker-proxy-1.13.1
```

**预估时间**：15 分钟

---

#### 阶段 7：安装和配置（复杂度：⭐⭐）

```bash
# 复制二进制到系统路径
sudo cp bundles/1.13.1/dynbinary-daemon/dockerd-1.13.1 /usr/bin/dockerd
sudo cp bundles/1.13.1/dynbinary-daemon/docker-proxy-1.13.1 /usr/bin/docker-proxy
sudo cp /usr/local/bin/docker-runc /usr/bin/docker-runc
sudo cp /usr/local/bin/docker-containerd /usr/bin/docker-containerd
sudo cp /usr/local/bin/docker-containerd-shim /usr/bin/docker-containerd-shim

# 创建 systemd 服务
sudo cp contrib/init/systemd/docker.service /usr/lib/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable docker
sudo systemctl start docker

# 验证
docker version
```

**预估时间**：10 分钟

### 总结：手动编译 vs 容器化构建

| 对比项 | 容器化构建 | 手动编译 |
|-------|-----------|---------|
| **复杂度** | ⭐⭐ 低 | ⭐⭐⭐⭐ 高 |
| **时间投入** | 30-40 分钟（自动） | 2-3 小时（手动） |
| **出错概率** | 低（已验证的环境） | 高（依赖复杂） |
| **可重复性** | 高（Dockerfile 固化） | 低（手动步骤） |
| **调试难度** | 低 | 高 |
| **环境污染** | 无（隔离容器） | 有（系统级安装） |
| **适用场景** | 标准构建 | 特殊环境/学习 |

## 实用建议

### 1. 镜像替换的具体步骤

```bash
cd ~/docker-patch-test/moby-1.13.1

# 创建修改后的 Dockerfile
cat > Dockerfile.aarch64.ubuntu20 <<'EOF'
FROM arm64v8/ubuntu:20.04

# 设置非交互式安装
ENV DEBIAN_FRONTEND=noninteractive

# 安装依赖（修改后的包名）
RUN apt-get update && apt-get install -y \
    apparmor \
    aufs-tools \
    automake \
    bash-completion \
    btrfs-progs \
    build-essential \
    cmake \
    createrepo \
    curl \
    dpkg-sig \
    g++ \
    gcc \
    git \
    iptables \
    jq \
    libapparmor-dev \
    libc6-dev \
    libcap-dev \
    libltdl-dev \
    libsqlite3-dev \
    libsystemd-dev \
    mercurial \
    net-tools \
    parallel \
    pkg-config \
    python3-dev \
    python3-mock \
    python3-pip \
    python3-websocket \
    gccgo \
    iproute2 \
    iputils-ping \
    vim-common \
    --no-install-recommends

# ... 后续保持原 Dockerfile 的其他内容不变
EOF

# 从原 Dockerfile 复制剩余部分（从第57行开始）
tail -n +57 Dockerfile.aarch64 >> Dockerfile.aarch64.ubuntu20

# 使用新 Dockerfile 构建
export DOCKERFILE=Dockerfile.aarch64.ubuntu20
make build
```

### 2. 验证新镜像的兼容性

```bash
# 测试构建环境
docker run -it --rm arm64v8/ubuntu:20.04 bash -c \
    "apt-get update && \
     apt-get install -y build-essential git golang-go && \
     go version && \
     gcc --version"

# 如果成功，说明镜像可用
```

### 3. 手动编译的最小化方案

如果确实需要手动编译，可以跳过某些组件：

```bash
# 最小化构建（跳过测试、文档等）
export DOCKER_BUILDTAGS="exclude_graphdriver_devicemapper"  # 跳过 devicemapper
./hack/make.sh dynbinary  # 只构建二进制，不运行测试
```

## 文档总结

### 镜像替换

✅ **完全可行**，推荐使用 **Ubuntu 20.04** 或 **Ubuntu 18.04**  
⏱️ **工作量**：5-10 分钟（修改 5 处）  
🎯 **成功率**：> 95%

### 手动编译

⚠️ **可行但不推荐**  
⏱️ **工作量**：2-3 小时  
🐛 **复杂度**：高（7 个阶段，多个依赖）  
🎯 **适用场景**：学习、特殊环境、无 Docker

### 最终推荐

**使用容器化构建 + 替换为 Ubuntu 20.04 镜像**，这是最佳平衡点。
